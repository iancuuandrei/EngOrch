# v1.0.5 isolated writer candidate

This candidate adds opt-in resource-bounded isolated initial writers. A complete
initial implementation cohort must fit declared CPU, memory, runtime,
verification and exact provider/model/profile capacities before any writer
invocation. Each writer gets a confirmed pristine child worktree, its own task
scope and candidate binding. Proposals are exported from child evidence and
reprepared against the parent before one aggregate file effect. Native gates
and review inspect the combined parent result. Later bounded repairs run
serially against that parent candidate.

The policy uses `plan-graph-v7`; old serial and two-writer planner recipes retain
their identities. The new mode is not a generic concurrent merge engine.
UNKNOWN child creation remains unresolved and is never recreated. The initial
cohort is frozen once; verification-slot estimates may be zero for writers that
do not own verification work, while global verification capacity remains positive.

The same increment adds explicit `go-source-context-v2`: version 3 admission
records with a separate identity domain, 24 KiB Go context and 8 KiB complete
generator-supporting files. Literal generation ownership is discovered from
committed directives and narrow Makefile/embed relationships. Only relations
whose owner and output are both admitted with matching source hashes enter the
Go graph; other observed chains remain partial metadata. Compact planner input
excludes full source inventories. Persisted generation files are checked
directly against their full source hashes; oversized files are omitted.

This follows two demonstrated failures of v1.0.3: no fixed-six acceptance gain,
increased matched token use, and an unused invented template in the numeric task.
The new mode has no real coding-task result yet and is not enabled by default.
