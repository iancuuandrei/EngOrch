## Whole-system efficiency

Memory is one resource dimension. Measure end-to-end and stage latency, CPU time,
allocations, resident/peak memory, I/O operations and bytes, queue wait, useful
parallelism, cache reuse, replay/hash/context overhead, and model usage separated
into input, cached input, uncached input, output and reasoning tokens. Record
unknown observations explicitly. Process-only Windows counters exclude child
processes; I/O counters include pipes and other nondisk activity. These counters
do not establish whole-workflow resource totals.

Optimize measured repeated work and expensive stages while retaining output
quality, durable evidence, verification and external-effect ownership. Compare
successful, repaired and isolated real workflows before claiming an efficiency
gain. A lower token total alone does not establish lower cost or faster execution.

Evaluate useful verified tasks per unit of time and cost, including failed calls,
corrections and retries. Track time to first useful result, queue contention,
worker utilization, subprocess startup, disk footprint and provider/network wait
where observable. Separate cold-cache and warm-cache measurements and record
cache hits, misses, invalidations and avoided work. Provider cached-input tokens
and Fabric's local caches are distinct measurements; unknown pricing remains
unknown. Check context duplication and growth across turns as well as total
tokens. Avoid improving one counter by shifting work to unmeasured child
processes, increasing retries or reducing verified task quality.
