# Working context

This advisory procedure grants no authority. Use it only when the invocation
explicitly supplies a working-context replacement contract. The controller owns
task identity, source, candidate, dependencies, scope, permissions, effect state,
repair budgets, checks, review and acceptance. Notes never override those fields.

Keep useful engineering state rather than a chronological transcript: relevant
files/symbols, current hypotheses, unresolved findings, constraints, failed
approaches with reasons, observed test outcomes, open questions and next actions.
Optional headings include CURRENT OBJECTIVE, IMPORTANT CONSTRAINTS, RELEVANT
FILES/SYMBOLS, VERIFIED FACTS, FINDINGS and NEXT ACTIONS. Choose any useful form.

Remove repeated source excerpts, obsolete hypotheses, resolved findings,
successful command noise, duplicated tool output and irrelevant narration.
Distinguish observations from guesses. Reference original evidence when useful;
removing a note does not remove evidence from Fabric's durable journal.

Return only your own bounded replacement using the exact expected identity/hash
supplied by Fabric. Do not write a note file, acquire more evidence merely to fill
context, or include credentials. A structured engineering handoff belongs in the
ordinary result; private retention notes are not a task completion claim.
